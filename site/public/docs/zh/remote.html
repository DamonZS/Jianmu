远程 jianmu

一个 jianmu 可以服务多台电脑。在保存供应商的那台电脑上（你的台式机、一台服务器、Docker 里的 NAS）登录、配置一次供应商和路由组，然后在其他每台电脑上把这个 jianmu 添加为一个供应商：远程 jianmu（Remote jianmu）。

共享的 jianmu其他电脑上的 jianmu
供应商、订阅、密钥保存并登录在这里通过远程 jianmu 使用
路由组在这里创建以 office/group/… 选用
Agent它自己的仍由本机的 jianmu 配置
用量与额度在这里统计和读取在这里显示，带上远程的名字

你面前的电脑仍然运行 jianmu：它配置本机的 Agent、为它们选模型、保存它们的会话。只有模型来自另一台。

1. 共享主 jianmu

  1. 打开共享在保存供应商的电脑上：设置 → 网络与共享 → 局域网共享 → 开启。jianmu 随即在局域网上监听，并生成一个名为 Jianmu 的网关密钥。开关下方的 地址 一行显示其他电脑访问它的地址，例如 http://192.168.1.20:3425。
  2. 给每台电脑一个密钥网关 → 网关密钥，或 jianmu gateway-key add "Laptop"，它会打印 sk-jianmu-key-…。每个密钥可以有自己的每日、每周或每月上限和可用模型，它的调用按它的名字统计。

共享关闭时，桌面版 jianmu 只在本机监听，其他电脑访问不到。Docker 里的 jianmu 则通过发布的端口访问，不论是否共享，都会向容器外的每个调用方要网关密钥；见 Docker。

2. 在其他电脑上添加

需要第 1 步里的地址和一个密钥。以下任一方式都可以：

  • 应用：在 供应商 页按 ＋ 添加供应商，在最后的 另一台电脑上的 jianmu 下选 Remote jianmu，填入地址和密钥。
  • TUI（jianmu tui）：在 Providers 页按 a，选 Remote jianmu，输入地址和密钥。在它那一行，w 修改地址，m 重新获取列表。
  • CLI：
Shell 
jianmu provider add remote-jianmu sk-jianmu-key-… url=http://192.168.1.20:3425 id=office
jianmu models            # office/… 是共享 jianmu 的模型
jianmu provider refresh office   # 重新获取列表

id= 是这个供应商在本机的名字，也是它的模型 id 的开头（office/…）。地址可以写成 192.168.1.20:3425（默认 http://），后面带 /v1，或者写根地址：jianmu 都会把各个 API 接到上面。每台共享出来的电脑添加一个远程 jianmu，用不同的 id。

能用到什么

  • 它的模型，和它自己的 Agent 看到的一样：office/relay-a/claude-sonnet-5，标签是 Claude Sonnet 5 · Relay A · office。id 不变，名字只出现在标签里。在本机像其他模型一样为 Agent 选用。
  • 它的路由组，以 office/group/… 出现。路由在共享的 jianmu 上用它的账号决定。
  • 所有 API。请求按 Agent 使用的 API 原样转发（Anthropic Messages 和 token 计数、Responses、Chat Completions）。共享 jianmu 的供应商只用另一种 API 提供的模型，只转换一次，不会在两台电脑上各转一次。Responses 走 HTTP（包括 SSE），不走 WebSocket。
  • 图像和视频。它的图像和视频模型会被自动识别，经由它的图像生成、编辑和视频 API 提供。
  • System One。它的决策模型（Jev、Clef，以及你自己命名的模型）接到它的 /v1/systemone，作为决策模型而不是对话模型出现。刷新供应商列表可以发现新的。只写 office 时使用列表里的第一个决策模型。
  • Embeddings、rerank、语音转文字和文字转语音发往它对应的 API。它们在 Agent 列表里保持远程上的样子；出现在列表里并不代表能用来对话。
  • 价格。每个模型在本机按共享 jianmu 的计价（那边手动设的价格，否则是供应商的标价），两台电脑算出来一样。在本机设的价格优先。

额度与用量

用量页、菜单栏和 jianmu quota 会显示共享 jianmu 的订阅卡片，带上它的名字（Codex · office，id office/codex），内容是那边最近一次读取的结果：只有保存登录的电脑去问厂商。在本机刷新卡片会让那边再读一次，最多每 30 秒一次。Codex 重置或 WorkBuddy 签到要在那台电脑上，用它自己的应用、TUI 或 CLI 来做。那边限了额度、模型或账号的密钥看不到它的任何卡片：本机只显示这把密钥自己的卡片和它的限额。

共享的 jianmu 把本机的请求记在本机所用网关密钥的名字下，并记下应答的账号。

短期密钥

在沙箱里启动 agent 的程序，可以给每个 agent 发一把自己的网关密钥，到期自动失效。密钥有效期 1 分钟到 30 天，可以限定部分模型、部分账号、整个有效期内的 token 数或花费，或只读。密钥本身只在返回里出现一次。

Shell 
curl -s -X POST http://127.0.0.1:3425/v1/jianmu/keys \
  -d '{"name":"sandbox-1","ttl":"1h","models":["office/codex/gpt-5"],"tokens":200000}'
# {"id":"k…","name":"sandbox-1","key":"sk-jianmu-…","expires":"…","models":[…],"limit":{…}}
curl -s http://127.0.0.1:3425/v1/jianmu/keys              # 你签发的密钥（已遮盖）
curl -s -X DELETE http://127.0.0.1:3425/v1/jianmu/keys/k…  # 提前吊销

本机上的程序不带密钥即可调用；浏览器里的网页不行。其他电脑、容器或 CI 要带一把你允许签发的网关密钥来调用，它签发的每把密钥都受它约束：用不了它不能用的模型和账号，不会比它晚过期，花费也计入它的限额。关掉或删掉它，它签发的密钥立刻失效。命令行里也一样，只输出密钥本身：

Shell 
jianmu gateway-key issue --ttl 1h --name sandbox-1 --models office/codex/gpt-5 --tokens 200000
jianmu gateway-key issuer <id> on    # 允许这个密钥签发密钥
jianmu gateway-key issue --ttl 30m --from <id> --read-only --json
jianmu gateway-key list               # until 10-31 14:00、expired、issued by …

过期的密钥在每个 API 上都返回 401 并说明原因（“the gateway key "sandbox-1" expired at …: ask for a new one”），本机请求也一样。一小时后它会被删掉。

GitHub Actions 的密钥

GitHub Actions 的任务不用在仓库 secrets 里放网关密钥，也能拿到短期密钥：用 GitHub 给它的 OIDC token 来换。写一条规则，指定仓库（还可以指定分支、environment 或任意 claim，精确值或带 *）、签发所用的网关密钥和有效期：

Shell 
jianmu gateway-key issuer <id> on
jianmu gateway-key oidc add --key <id> --repo owner/app --ref refs/heads/main --ttl 1h
# 输出规则 id 和它的 audience：jianmu-<规则 id>
jianmu gateway-key oidc list
jianmu gateway-key oidc remove <rule id>

在 workflow 里向 GitHub 要一个带规则 audience 的 token，POST 到 /v1/jianmu/keys/oidc：

YAML 
permissions:
  id-token: write
steps:
  - name: Get a jianmu key
    run: |
      TOKEN=$(curl -s -H "Authorization: Bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN" \
        "$ACTIONS_ID_TOKEN_REQUEST_URL&audience=jianmu-<rule id>" | jq -r .value)
      KEY=$(curl -s -X POST https://<your jianmu>/v1/jianmu/keys/oidc \
        -H "Authorization: Bearer $TOKEN" -d '{"ttl":"30m"}' | jq -r .key)
      echo "::add-mask::$KEY"
      echo "JIANMU_KEY=$KEY" >> "$GITHUB_ENV"

换到的密钥由规则里的网关密钥签发，和其他签发的密钥一样受它约束，有效期不超过规则所写，名字是仓库、分支和运行编号。其他仓库或分支的 token、过期的 token、已经换过的 token 会收到 401 和原因。只有 jianmu 共享时其他电脑才能调用这个接口，被拒的 token 计入失败认证次数。没有规则就什么都换不到。

统计 API

用量页上的内容也以 JSON 提供给本机；共享 jianmu 时，也提供给带网关密钥的请求。受预算、模型或账号限制的密钥只能看到自己的请求和限额；主人为它打开额度后（jianmu gateway-key quotas <id> on），还能看到它可用部分的额度。

  • /v1/jianmu/usage?period=today|7d|30d|all：总量，以及按模型、agent、提供商、账号和网关密钥的分项。
  • /v1/jianmu/usage/requests：请求记录，支持 period、day、offset、limit，以及筛选 model、agent、provider、account、callerKey、failed=1、retried=1 和 q。
  • /v1/jianmu/quotas：每个订阅的额度窗口（?kept=1 不去问厂商）；/v1/jianmu/quotas/history?days=：剩余额度的历史，最多 45 天。
  • /v1/jianmu/limit：这把密钥自己的限额、过期时间，以及签发它的密钥的限额；受限的密钥还会告诉它受什么限制（heldTo）、可用的模型（models），以及能否看到额度（quotas、quotaProviders）。
  • /v1/jianmu/concurrency：每个账号正在进行的请求。
Shell 
curl -s 'http://127.0.0.1:3425/v1/jianmu/usage?period=7d'
curl -s 'http://127.0.0.1:3425/v1/jianmu/usage/requests?period=today&callerKey=k…&failed=1&limit=50'
curl -s 'http://127.0.0.1:3425/v1/jianmu/quotas?kept=1'
curl -s 'http://127.0.0.1:3425/v1/jianmu/quotas/history?days=14'
curl -s http://127.0.0.1:3425/v1/jianmu/limit -H 'Authorization: Bearer sk-jianmu-…'
curl -s http://127.0.0.1:3425/v1/jianmu/concurrency

出问题时

看到的提示怎么做
“jianmu isn’t shared on the local network” 或 “remote jianmu isn’t shared”在那台电脑上打开 局域网共享
“remote jianmu didn’t take this key”（401）用它的一个已启用的网关密钥：那边的 网关 → 网关密钥
某个模型 403这个密钥可能只能用部分模型：在那台电脑上用 jianmu gateway-key models <id> 查看或修改。只写 office 会请求 System One 的第一个决策模型，不管密钥允许什么；请用完整的 office/provider/model id
“couldn’t reach the remote jianmu”检查地址、那边的 jianmu 是否在运行并打开了共享、防火墙是否放行该端口
没有 System One 模型，或 “doesn’t share its quotas”更新那台电脑上的 jianmu，再在本机刷新列表
不在家时，通过 Tailscale 或 WireGuard 等 VPN、用它在 VPN 里的地址访问共享的 jianmu。不要把它的端口开放到互联网。
