Goose

工作原理 接入 Goose 模型和思考强度 jianmu 写了什么 切回 常见问题

文档 · 指南

让 Goose 用任意模型

Goose 是 Block 开源的 Agent，使用配置里的供应商和模型。jianmu 把自己作为自定义供应商加进 Goose，于是 Goose 的 CLI 和桌面版都能用你在 jianmu 里的任何模型：DeepSeek、Kimi、GLM、Qwen、OpenAI Key，或 ChatGPT、Copilot 订阅，不用往 Goose 里贴 Key。

Goose 的设置在 ~/.config/goose/config.yaml（设置了 $XDG_CONFIG_HOME 时在其下；Windows 上在 %APPDATA%\Block\goose\config）。jianmu 在旁边写一个自定义供应商 custom_providers/jianmu.json，包含网关地址、一个 Goose 专用的 Key 和 jianmu 的模型，再把它设为 Goose 使用的供应商。网关把每个请求翻译给该模型的供应商，工具调用和推理都保留。WSL 里的 Goose 也一样设置，用发行版能访问到的网关地址。

接入 Goose

  1. 在 jianmu 里添加供应商在 供应商 页添加 API Key，或登录一个订阅。
  2. 在 Goose 那一行选模型在 Agent 页，给 Goose 一行选一个模型。选择器里也列出 Goose 自己配置过的供应商的模型。
  3. 重启 GooseGoose 在启动时加载自定义供应商：退出并重新打开桌面版，重新打开 goose 会话。
终端
jianmu goose deepseek/deepseek-v4-pro    # Goose 用 DeepSeek
jianmu goose                             # 查看 Goose 当前的模型

模型和思考强度

jianmu 为 Goose 列出的每个模型都带上了上下文窗口，Goose 不必去猜，也标明了能否接受思考强度。这一行还能设置 GOOSE_THINKING_EFFORT，即 Goose 对会思考的模型请求的强度：off、low、medium、high 或 max。

终端
jianmu goose effort high
jianmu goose effort default    # 恢复 Goose 的默认

jianmu 写了什么

Goose 记录当前供应商有两种写法：active_provider 加 providers.jianmu.model，以及较早的 GOOSE_PROVIDER 和 GOOSE_MODEL。jianmu 按你的配置已有的写法来写。你自己加到 jianmu 供应商文件里的字段，比如 timeout_seconds、headers 或 toolshim，在 jianmu 重写模型时会保留。

切回

在 Goose 那一行选你自己供应商的模型、把这一行从 jianmu 移除，或运行 jianmu goose default。Goose 不再用 jianmu 的模型后，jianmu 会删除它的供应商文件。

常见问题

Goose 能用我的 ChatGPT 订阅吗？

能。在 jianmu 里登录 ChatGPT，在 Goose 那一行选一个 GPT 模型。Goose 把请求发给 jianmu，由 jianmu 使用订阅。

Goose 里看不到 jianmu 的模型。

Goose 只在启动时读取自定义供应商。退出并重新打开 Goose，再开一个新的 goose 会话。

Goose 桌面版也能用吗？

能。CLI 和桌面版读同一份配置，重启后都会用 Goose 那一行的模型。

WSL 里的 goose 能用吗？

能。jianmu 也会设置 WSL 发行版里的 Goose，用发行版能访问到的网关地址。

更多 Agent 用同样的模型：OpenCode 接入其他模型、Claude Code 接入其他模型、让 Cline 用任意模型、让 Droid 用任意模型。遇到报错？见 常见错误排查，或到 GitHub Issues 提问。
