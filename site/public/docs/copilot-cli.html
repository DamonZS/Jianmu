Copilot CLI on any model

GitHub Copilot CLI can run on model providers of your own (bring your own key), which needs no GitHub sign-in. jianmu adds itself to Copilot CLI as one, so copilot can run on any model you have in jianmu: DeepSeek, Kimi, GLM, Qwen, an OpenAI key, or a ChatGPT subscription, with no key pasted into Copilot.

Copilot CLI keeps its folder in ~/.copilot (or $COPILOT_HOME). Its own providers are in providers.json there (or $COPILOT_PROVIDERS_CONFIG). jianmu adds a provider named jianmu to that file, OpenAI-compatible, with the gateway’s address and a key of Copilot’s own, and adds jianmu’s models beside it, each with its name, context window and output limit. Then it sets model in settings.json to jianmu/<model>. The gateway translates each request for the model’s provider, tool calls and reasoning included.

Connect Copilot CLI

  1. Add providers in jianmuIn the Providers tab, add an API key or sign in to a subscription.
  2. Pick a model on Copilot CLI’s rowIn the Agents tab, choose a model under jianmu.
  3. Start copilotIt runs on that model. Copilot’s own /model lists jianmu’s models too.
Terminal
jianmu copilot deepseek/deepseek-v4-pro    # settings.json: jianmu/deepseek/deepseek-v4-pro
jianmu copilot                             # what Copilot CLI runs on now

The row also lists Copilot’s own models and auto, Copilot’s own choice, for when you want GitHub’s models back.

Effort

The row sets effortLevel, which Copilot saves beside the model: the model’s own levels, or low, medium, high and xhigh when Copilot’s list doesn’t name them. Copilot clears it when its own /model changes the model.

Terminal
jianmu copilot effort high
jianmu copilot effort default

Your providers.json

jianmu owns only the provider named jianmu and the models that name it. Your other providers, their models and any other key in the file stay where they are, and so does a key you add to jianmu’s provider yourself. A providers.json that isn’t valid JSON is left alone, never written over. When jianmu’s models change, jianmu brings its entries up to date, and writes the file only when they would change.

Switch back

Pick one of Copilot’s own models on the row, or run jianmu copilot default. That removes model from settings.json and takes jianmu’s provider and models out of providers.json, leaving the rest.

FAQ

Do I need a GitHub Copilot subscription?

No. Copilot CLI’s own providers need no GitHub sign-in, so jianmu’s models work without a Copilot plan.

Can Copilot CLI use my ChatGPT subscription?

Yes. Sign in to ChatGPT in jianmu and pick a GPT model under jianmu on Copilot CLI’s row. Copilot sends its requests to jianmu, which uses the subscription.

Why does settings.json say jianmu/deepseek/…?

Copilot names a model of one of its providers as provider/model, and jianmu’s provider is called jianmu. On the command line you can leave the jianmu/ out.

Can I keep my own BYOK providers?

Yes. jianmu only touches its own provider and models in providers.json; yours stay as they are.
