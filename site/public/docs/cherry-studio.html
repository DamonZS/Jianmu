Every model in Cherry Studio, through jianmu

Cherry Studio is a desktop chat client that takes any OpenAI-compatible provider. jianmu adds itself there as one provider, named jianmu, so every model you have in jianmu shows up in Cherry Studio: providers with an API key and the Claude, ChatGPT or Copilot subscriptions you signed in to.

jianmu runs a gateway on your computer at http://127.0.0.1:3425. It speaks the OpenAI Chat Completions API and translates each request for the provider behind the model, Anthropic’s, Google’s or a subscription’s, with streaming, tool calls and reasoning. Cherry Studio sees one OpenAI-compatible provider at http://127.0.0.1:3425/v1.

Cherry Studio keeps its providers in its own database, and jianmu never writes to it. It adds itself through Cherry Studio’s add-provider link instead, and you confirm it in Cherry Studio. This works in Cherry Studio 1.x and 2.x.

Add jianmu to Cherry Studio

  1. Add providers in jianmuIn the Providers tab, add an API key (DeepSeek, Kimi, GLM, Qwen, OpenRouter…) or sign in to a subscription.
  2. Open the Agents tabjianmu lists Cherry Studio once it has run on this computer, including a data folder you moved elsewhere.
  3. Click Add jianmuOn Cherry Studio’s row, press Add jianmu. Cherry Studio opens its model provider settings with jianmu filled in: name jianmu, type OpenAI, the gateway’s address and a key.
  4. Confirm it in Cherry StudioNothing is added until you do.

If nothing opens, no app on this computer handles Cherry Studio’s links yet: open Cherry Studio once, or install it again, then click Add jianmu again.

Pick the models

Cherry Studio lists a provider’s models from /v1/models, so the jianmu provider offers every model jianmu has, named provider/model (for example deepseek/deepseek-v4-pro). Add the ones you want to the jianmu provider in Cherry Studio, and choose them in a chat like any other model.

A provider you add in jianmu later shows up the next time Cherry Studio fetches the list; there is nothing to change in Cherry Studio. Several accounts behind one model, rest periods after a 429 and failover work as they do for every agent.

From a terminal

Terminal
jianmu cherrystudio add      # opens Cherry Studio to add jianmu, confirm it there

cherry-studio works as the name too.

How jianmu knows it was added

Once Cherry Studio has a provider at the gateway’s address, the row shows jianmu instead of the button. jianmu reads Cherry Studio 2.x’s database for this, read-only. Cherry Studio 1.x keeps providers where jianmu doesn’t read them, so there the button stays.

Usage and keys

On a gateway that isn’t shared, the key in the link is Cherry Studio’s own, so its requests are counted as Cherry Studio’s in jianmu’s Usage, apart from your coding agents. When the gateway is shared on your network with gateway keys, the link carries a key that works there.

FAQ

Do I need an API key to use Claude or ChatGPT in Cherry Studio?

No. Sign in to a Claude, ChatGPT or Copilot subscription in jianmu, and its models appear in the jianmu provider in Cherry Studio.

Does jianmu change Cherry Studio’s settings?

No. jianmu opens Cherry Studio’s own add-provider dialog, and you confirm it. It only reads Cherry Studio’s database to show whether jianmu was added.

What address and type does the jianmu provider use?

Type OpenAI, at http://127.0.0.1:3425/v1, or the gateway address you set in jianmu.

Why don’t I see a new model in Cherry Studio?

Cherry Studio shows models you added to the provider. Fetch the jianmu provider’s model list again and add the new one.

Cherry Studio isn’t in jianmu’s Agents tab.

jianmu lists it once Cherry Studio has run on this computer. Open Cherry Studio once, then look again.
