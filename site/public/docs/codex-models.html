Use DeepSeek, Kimi, GLM, Claude or any model in Codex

Codex speaks one API, OpenAI Responses. jianmu puts a gateway on your computer that speaks it for every provider you add, and writes Codex’s config.toml for you. The models then show in Codex’s /model, with their reasoning efforts.

The gateway runs at 127.0.0.1:3425. When a provider serves the Responses API itself, as DeepSeek and the Zhipu GLM Coding Plan do, Codex’s request is passed on as it is. When it serves only Chat Completions or Anthropic Messages, as Kimi, MiniMax and Qwen do, or a Claude subscription, jianmu translates the request and the reply, streaming and tool calls included.

Chinese models

DeepSeek, Kimi and Kimi Code, Zhipu GLM (pay as you go or Coding Plan), Z.ai, MiniMax and Qwen, each with its China endpoint where it has one.

Claude

Your Claude subscription’s models, or an Anthropic key’s.

Anything else

Any OpenAI- or Anthropic-compatible URL and key, Copilot and Antigravity accounts, Ollama and LM Studio.

Set it up

  1. Add the providerIn jianmu’s Providers tab, press ＋ Add provider, pick DeepSeek, Kimi, Zhipu GLM, MiniMax or Qwen, paste your API key and save. jianmu asks the vendor which models it serves.
  2. Pick the model for CodexIn the Agents tab, click the model on the Codex row and choose one, such as deepseek/deepseek-v4-pro. The effort slider under the list sets its reasoning effort. jianmu writes both into ~/.codex/config.toml.
  3. Restart CodexCodex builds its model list when it starts. Restart the Codex app, and open new codex sessions, after a switch.

The same from a terminal:

Terminal
jianmu provider add deepseek sk-…
jianmu models                        # every model, as provider/model
jianmu codex deepseek/deepseek-v4-pro
jianmu codex effort high
Zhipu GLM Coding Plan. When you add Zhipu GLM or Z.ai, pick the plan your key is for. A Coding Plan key has its own endpoints, and sent to the pay-as-you-go one it is told it has no balance.

The models in Codex’s /model

jianmu’s models are listed in Codex’s /model beside its own, so you can switch there too. Each one carries what Codex needs to run it: its reasoning efforts and default effort, its context window and the base instructions Codex sends with it.

How they get there depends on how Codex is signed in:

  • Signed in to ChatGPT. Codex keeps its own OpenAI provider and your sign-in. jianmu points it at the gateway with openai_base_url; Codex’s own models still go to OpenAI on your account, and jianmu’s models join them in /model.
  • Not signed in, or signed in with an API key. jianmu becomes Codex’s provider, and the list comes from a catalog file jianmu writes, jianmu-models.json beside config.toml.

What changes in config.toml

jianmu changes only the keys it needs in ~/.codex/config.toml. Comments, ordering and your other settings stay.

KeySet to
modelThe model you picked
model_reasoning_effortThe effort, when you set one
openai_base_urlThe gateway’s address. A base URL of your own stays
model_provider"jianmu", when jianmu is the provider
model_catalog_jsonThe path of the catalog file, jianmu-models.json, when jianmu is the provider
[model_providers.jianmu]name, base_url (the gateway’s /v1), wire_api = "responses", and the gateway’s key. Your vendor keys stay in jianmu
~/.codex/config.toml
model = "deepseek/deepseek-v4-pro"
model_provider = "jianmu"
model_catalog_json = "/Users/you/.codex/jianmu-models.json"

[model_providers.jianmu]
name = "jianmu"
base_url = "http://127.0.0.1:3425/v1"
wire_api = "responses"

That is the shape when jianmu is the provider; the table also carries the gateway’s key and a header. Signed in to ChatGPT, only openai_base_url and model are set at the top. The [model_providers.jianmu] table stays once written. A Codex thread keeps the provider it was started on, and a thread started on jianmu can’t be opened again without it.

Going back to OpenAI’s models

Pick one of Codex’s own models on its row, or run jianmu codex default. jianmu takes model_provider, model_catalog_json and the base URL back out and puts back the provider and model you had. A provider of your own at the top stays. Threads started on jianmu are moved back to the provider Codex is on, so Codex lists them, and a copy is kept in jianmu’s trash.

Claude in Codex

Sign in to your Claude subscription in jianmu: ＋ Add provider, then the Claude tile. Its models are claude/… in Codex’s picker. jianmu translates Codex’s Responses requests into Anthropic Messages and the replies back.

Terminal
jianmu accounts add claude     # sign in to a Claude account
jianmu models | grep '^claude/'
jianmu codex claude/…

Requests on a Claude subscription run through the Claude Code installed on your computer, so keep it installed. An Anthropic API key works too: add Anthropic as a vendor and pick an anthropic/… model.

Routing over several keys

  • Several keys for one vendor. Add them all to the provider and tick each one. Routing on the provider says how requests spread, and Fallback lists models to use when it is out of quota or down.
  • One model from several providers. When two of your providers serve the same model, jianmu makes the group auto/<model> by itself. Pick it for Codex.
  • Your own group. New group in the Routing tab puts any models behind one name, group/<id>.

The routing modes are in Get started.

FAQ

Do I write [model_providers] myself?

No. jianmu writes Codex’s config.toml when you pick a model. You don’t export OPENAI_BASE_URL either.

Does my ChatGPT sign-in still work?

Yes. Signed in to ChatGPT, Codex keeps its own provider and sign-in. Its own models go to OpenAI on your account, and jianmu’s are added beside them.

I picked a model, but Codex’s /model doesn’t show it.

Codex reads its model list when it starts. Restart the Codex app and open a new codex session.

Can I set the reasoning effort?

Yes, on the Codex row’s effort slider, with jianmu codex effort high, or in Codex’s /model, which lists each model’s efforts.

Which Chinese models can Codex use?

Any that a provider you add serves. jianmu has presets for DeepSeek, Kimi, Kimi Code, Zhipu GLM, Z.ai, MiniMax and Qwen. Others can be added as a custom URL.

Does jianmu have to be running?

Yes, while Codex is on a model through jianmu: the gateway runs with the app. jianmu daemon install keeps it running as a service with no window.

How do I undo it?

Pick one of Codex’s own models in jianmu, or run jianmu codex default. jianmu’s keys come out, and your provider and model come back.
