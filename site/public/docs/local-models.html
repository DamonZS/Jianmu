Use Ollama or LM Studio models in Claude Code and Codex

Claude Code speaks Anthropic Messages and Codex speaks OpenAI Responses. A local model server speaks OpenAI Chat Completions, and some speak Anthropic Messages too. jianmu sits between them on your computer, so Claude Code and Codex can run on the models you pulled in Ollama or loaded in LM Studio.

The gateway runs at 127.0.0.1:3425. jianmu points the agent at it and sends each request on to your server. When the server speaks the agent’s API itself, the request is passed on as it is. When it doesn’t, jianmu translates the request and the reply, streaming and tool calls included.

Ollama, LM Studio

Presets with their default ports and no key. jianmu asks the server which models it has.

oMLX, MLX-Serve

MLX servers for Apple silicon, also presets.

Anything else

vLLM, llama.cpp’s server or any OpenAI-compatible URL, on this computer or another.

Supported servers

These are under On this machine when you add a provider:

ServerDefault addressAPIs jianmu uses
Ollamahttp://localhost:11434Chat Completions, Anthropic Messages
LM Studiohttp://localhost:1234Chat Completions
oMLXhttp://localhost:8000Chat Completions, Responses, Anthropic Messages
MLX-Servehttp://localhost:11234Chat Completions, Responses, Anthropic Messages

So Claude Code on Ollama, oMLX or MLX-Serve sends its requests to the server as they are, and on LM Studio jianmu translates them. Codex on oMLX or MLX-Serve goes as it is, and on Ollama or LM Studio jianmu turns its Responses requests into Chat Completions.

Set it up

  1. Start the serverPull or load a model in Ollama or LM Studio and leave the server running.
  2. Add it in jianmuIn the Providers tab, press ＋ Add provider and pick Ollama or LM Studio under On this machine. No key is needed. jianmu asks the server which models it has, and they show as ollama/… or lmstudio/….
  3. Pick the model for the agentIn the Agents tab, click the model on the Claude Code or Codex row and choose the local one. jianmu writes Claude Code’s settings.json or Codex’s config.toml. Start a new session to use it.

The same from a terminal:

Terminal
ollama pull qwen3
jianmu provider add ollama
jianmu models                     # every model, as provider/model
jianmu claude ollama/qwen3        # Claude Code
jianmu codex ollama/qwen3         # Codex

Inside the agent, Claude Code’s and Codex’s /model list jianmu’s models too, so you can move between a local model and a cloud one there. What changes in each agent’s config is in Models in Claude Code and Models in Codex.

Another port or another computer

If the server listens on another port, or runs on another computer such as a GPU box or a NAS, change Server address in the provider’s editor. Each of its URLs moves there and keeps its path.

Terminal
jianmu provider add lmstudio address=http://192.168.1.5:1234
jianmu provider set ollama address=192.168.1.20:11434
jianmu provider set ollama address=     # back to the default

A server behind HTTPS with a self-signed certificate can be reached with Don't check its certificate in the editor; it applies to that provider’s own hosts only.

vLLM, llama.cpp and other servers

A server with no preset is added as Custom: paste its URL, such as http://localhost:8080/v1, and press Detect APIs. jianmu sends the smallest request to Chat Completions, Responses, Anthropic Messages and Gemini at that URL and keeps the ones that answer. The key can be left empty for a server that needs none.

Context window

Agents plan around how long a request the model takes. Claude Code takes a model it doesn’t know for 200K, and Codex compacts a conversation at 90% of the window it is told. A local model is often loaded with a much smaller window, so tell jianmu the real one: Context window under Advanced in the provider’s editor, for every model or one of them. jianmu passes it on to the agents.

Terminal
jianmu provider set ollama context=32k
jianmu provider set ollama context.qwen3=128k

Masking

jianmu’s privacy masking replaces keys, tokens and other secrets with placeholders before a request leaves the gateway, a request to a local server too. When the model runs on your own computer or network, you can turn on Send requests unmasked in its editor, or run jianmu provider set ollama unmasked=yes. It is your call: Ollama’s cloud models, or a relay you run locally, pass a request on to a vendor whatever the address.

FAQ

Can Claude Code use Ollama?

Yes. Add Ollama in jianmu and pick one of its models for Claude Code. jianmu writes the gateway’s address into Claude Code’s settings.json, and Ollama’s Anthropic-compatible API takes Claude Code’s requests as they are.

Can Codex use Ollama or LM Studio?

Yes. Codex speaks only the Responses API, so jianmu turns its requests into Chat Completions for Ollama and LM Studio, and the replies back, tool calls included. oMLX and MLX-Serve take Responses themselves.

Do I need an API key?

No. The local presets take none. A server you secured with a key can have it in the provider’s editor.

Can the model run on another computer?

Yes. Set the provider’s Server address to that computer, such as http://192.168.1.20:11434.

Why does Claude Code fail on long conversations with a local model?

It assumes a model it doesn’t know takes 200K. Set the real Context window on the provider in jianmu, and Claude Code and Codex compact before they reach it.

How do I go back?

Pick one of the agent’s own models in jianmu, or run jianmu claude default or jianmu codex default. What jianmu wrote comes out, and what it replaced comes back.
