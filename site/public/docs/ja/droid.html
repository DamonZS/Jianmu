ドキュメント · ガイド

Droid を任意のモデルで

Droid は Factory のコーディング Agent で、自分のカスタムモデルで動かせます。jianmu は jianmu にあるモデルを Droid のカスタムモデルとして加えるので、droid で DeepSeek、Kimi、GLM、Qwen、OpenAI キー、ChatGPT や Copilot のサブスクを使えます。Droid にキーを貼る必要はありません。

Droid の設定は ~/.factory/settings.json にあります（$FACTORY_HOME_OVERRIDE があればその下）。jianmu は jianmu の各モデルを customModels に一つずつ加え、ゲートウェイのアドレスと Droid 用のキーを入れ、セッション開始時のモデル sessionDefaultSettings.model を設定します。各モデルはそのプロバイダ本来の API（Anthropic Messages、OpenAI Responses、Chat Completions）に載るので、ゲートウェイはそのまま中継します。WSL の droid も同じように、ディストリから見えるゲートウェイのアドレスで設定します。

Droid を接続

  1. jianmu にプロバイダを追加プロバイダ タブで API キーを追加するか、サブスクにサインインします。
  2. Droid の行でモデルを選ぶAgent タブで Droid の行のモデルを選びます。
  3. droid を再起動Droid は起動時に設定を読みます：開いているセッションはそのままなので、droid を起動し直してください。
ターミナル
jianmu droid deepseek/deepseek-v4-pro    # Droid を DeepSeek で
jianmu droid                             # Droid の今のモデル

モデルと思考レベル

jianmu のモデルは droid の /model ピッカーの Custom models にも並ぶので、セッション中に切り替えられます。推論するモデルには開始時の強さが付き、ピッカーにレベル（off、low、medium、high）が出ます。Droid 内蔵のモデルと同じものは Droid 自身のレベルと既定値を使います。Droid が OpenAI や Claude のものと読む名前のモデルは Droid が期待する API で書くので、セッション開始ごとの警告は出ません。

自分のモデル

自分で加えたカスタムモデルはそのまま jianmu のものより前に残り、id は変わりません。settings.json で jianmu の項目の名前や強さなどを変えた場合、jianmu はその値を残し、同期のたびに戻すのはアドレスとキーだけです。古い ~/.factory/config.json には触れません。

元に戻す

Droid の行から jianmu を外すか、jianmu droid default を実行します。jianmu は自分のカスタムモデルを削除し、元の既定モデルに戻します。

よくある質問

Droid で ChatGPT サブスクを使えますか？

使えます。jianmu で ChatGPT にサインインし、Droid の行で GPT モデルを選びます。droid のリクエストは jianmu に届き、jianmu がサブスクを使います。

モデルを変えたのに droid が古いモデルのままです。

Droid は起動時に設定を読みます。droid を再起動するか、セッション内で /model で切り替えてください。

/model であるモデルに思考レベルが出ないのはなぜですか？

そのモデルは推論しません。推論するモデルには jianmu が開始時の強さを付けるので、droid がレベルを出します。

jianmu は自分の BYOK モデルに触れますか？

触れません。自分のカスタムモデルはそのまま jianmu のものより前に残ります。

同じモデルを他のエージェントでも：OpenCode で他のモデル、Claude Code で他のモデル、Goose を任意のモデルで、Zed を任意のモデルで。エラーが出るときは よくあるエラーの直し方、または Discord で質問してください。
