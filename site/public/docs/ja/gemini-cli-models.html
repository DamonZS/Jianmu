Gemini CLI で DeepSeek・Kimi・GLM・Claude・GPT を使う

Gemini CLI が話すのは Google の Gemini API だけです。jianmu はあなたのコンピューター上に、追加したすべてのプロバイダについて Gemini API を提供するゲートウェイを置き、Gemini CLI をそこへ向けます。モデルは jianmu の Gemini CLI の行で選びます。

ゲートウェイは 127.0.0.1:3425 で動きます。OpenAI と Anthropic の API に加え、Gemini API の generateContent、streamGenerateContent、countTokens とモデル一覧を提供します。プロバイダが Gemini API を話す場合、リクエストはそのまま通ります。DeepSeek、Kimi、Zhipu GLM、Claude や ChatGPT のサブスクリプションのように話さない場合は変換されます：リクエストと応答、ストリーミング、ツール呼び出し、画像、推論も含みます。

中国のモデル

DeepSeek、Kimi と Kimi Code、Zhipu GLM（従量課金または Coding Plan）、Z.ai、MiniMax、Qwen。

サブスクリプション

jianmu でサインインした Claude、ChatGPT、Copilot、Antigravity アカウントのモデル。

その他

OpenAI 互換または Anthropic 互換の任意の URL とキー、Ollama、LM Studio。

セットアップ

  1. プロバイダを追加するjianmu の Providers タブで ＋ Add provider を押し、DeepSeek、Kimi、Zhipu GLM、MiniMax、Qwen のいずれかを選んで API キーを貼り付け、保存します。jianmu がベンダーに提供モデルを問い合わせます。
  2. Gemini CLI のモデルを選ぶAgents タブで Gemini CLI の行のモデルをクリックし、deepseek/deepseek-v4-pro などを選びます。jianmu はモデルを ~/.gemini/settings.json に、ゲートウェイのアドレスを ~/.gemini/.env に書き込みます。
  3. gemini を再起動するGemini CLI は起動時に設定を読みます。すでに開いているセッションは、起動時の設定のままです。

ターミナルからも同じことができます：

ターミナル
jianmu provider add deepseek sk-…
jianmu models                              # すべてのモデルを provider/model で表示
jianmu gemini model deepseek/deepseek-v4-pro

モデル ID は jianmu のもので、provider/model の形です。Gemini CLI の行は、gemini コマンドが PATH にあると表示されます。

Zhipu GLM の Coding Plan。 Zhipu GLM または Z.ai を追加するときは、キーに合ったプランを選んでください。Coding Plan のキーには専用のエンドポイントがあり、従量課金のエンドポイントに送ると残高がないと返されます。

~/.gemini で変わること

Gemini CLI は ~/.gemini/.env を読み込み、~/.gemini/settings.json を読みます。jianmu はこの 2 つで合わせて 4 つのキーを変更します：

ファイルキー設定される値
.envGOOGLE_GEMINI_BASE_URLゲートウェイのアドレス
.envGEMINI_API_KEYゲートウェイのキー（ベンダーのキーではありません。それは jianmu の中に残ります）
settings.jsonsecurity.auth.selectedTypegemini-api-key。Gemini CLI が Google のサインインではなくこのキーを送るようにします
settings.jsonmodel.nameprovider/model の形のモデル

最初のときに、jianmu はこれらのキーにあった値（自分のベース URL、API キー、サインイン方法、モデル）を保存しておきます。モデルが jianmu のものなのにサインイン方法が API キー以外に変えられると、Gemini CLI は Google に直接問い合わせます。その場合は jianmu の Gemini CLI の行にそう表示されます。

Google に戻す

Gemini CLI の行で Gemini CLI 自身の Gemini モデルを選ぶか、jianmu gemini default を実行します。jianmu は .env から GOOGLE_GEMINI_BASE_URL と GEMINI_API_KEY を取り除き、元のベース URL、キー、サインイン方法、モデルを戻します。どちらのファイルも手で編集する必要はありません。

行の auth 設定で、Gemini CLI が自分でどうサインインするかを選びます：Google（自分の Google アカウント）、API key、Vertex AI。jianmu に Google Gemini をプロバイダとして追加してあれば、API key はそのキーを Gemini CLI 用に .env に書き込みます。

ターミナル
jianmu gemini default   # jianmu の設定を外し、元の設定に戻す
jianmu gemini google    # 自分の Google アカウントでサインイン

サブスクリプションの Claude と GPT のモデル

jianmu でサブスクリプションにサインインします：＋ Add provider から Claude、ChatGPT、Copilot のタイルを選ぶと、jianmu がベンダー自身のサインインページを開きます。するとそのアカウントのモデルが、Gemini CLI の行に claude/…、codex/…、copilot/… として並びます。

ターミナル
jianmu accounts add codex           # ChatGPT アカウントにサインイン
jianmu gemini model codex/gpt-5.5

Gemini CLI が話すのはあくまで Gemini API です。jianmu が各リクエストをモデル向けに変換し、応答を戻します。Claude サブスクリプションでのリクエストは、コンピューターにインストールされた Claude Code を通じて送られるので、Claude Code はインストールしたままにしてください。詳しくはサブスクリプションを任意のエージェントで使うをご覧ください。

複数のキーでルーティング

  • 1 つのベンダーに複数のキー。 すべてをプロバイダに追加し、それぞれにチェックを入れます。プロバイダの Routing でリクエストの分散方法を決め、Fallback にはクォータ切れや障害のときに使うモデルを並べます。
  • 複数のプロバイダから同じモデル。 2 つのプロバイダが同じモデルを提供すると、jianmu はグループ auto/<model> を自動で作ります。それを Gemini CLI に選びます。
  • 圧縮には安いモデルを。 ルーティンググループの compacting ルールは Gemini CLI が会話を圧縮するときに一致するので、要約を安くて速いモデルに書かせられます。

ルーティングモードとルールははじめにで説明しています。

よくある質問

Gemini CLI で Gemini 以外のモデルを使えますか？

はい。Gemini API を提供するゲートウェイを通せば使えます。jianmu はそれをあなたのコンピューターで動かし、Gemini CLI をそこへ向けるので、追加したプロバイダのどのモデルでも動きます：DeepSeek、Kimi、GLM、Qwen、MiniMax、あるいは Claude、ChatGPT、Copilot のサブスクリプション。

GOOGLE_GEMINI_BASE_URL は自分で設定しますか？

いいえ。jianmu がそれと GEMINI_API_KEY を ~/.gemini/.env に書き込み、~/.gemini/settings.json で Gemini CLI を API キー認証にします。それまでの値は保存され、jianmu から切り替えると元に戻ります。

Gemini CLI がまだ Google にリクエストを送るのはなぜ？

サインイン方法が API キーになっていないからです。Google のサインインや Vertex AI では、Gemini CLI は Google に直接問い合わせます。jianmu でモデルを選び直すと API キーに戻ります。このとき jianmu の Gemini CLI の行に知らせが出ます。変更後は開いている gemini セッションを再起動してください。

ChatGPT や Claude のサブスクリプションを Gemini CLI で使えますか？

はい。jianmu でサインインし、Gemini CLI の行で codex/… または claude/… のモデルを選びます。Claude サブスクリプションでのリクエストは、コンピューターにインストールされた Claude Code を通じて送られます。

jianmu に Gemini CLI が表示されないのはなぜ？

jianmu は gemini コマンドが PATH にあるときに表示します。~/.gemini フォルダがあるだけでは数えません。Gemini CLI をアンインストールしても残り、Antigravity もそこにフォルダを置くからです。

WSL の Gemini CLI でも使えますか？

はい。jianmu は WSL ディストリビューション内の Gemini CLI も同じように設定し、ゲートウェイのアドレスはそのディストリビューションから届く形で書き込みます。

Gemini CLI を Google に戻すには？

jianmu で Gemini CLI 自身のモデルを選ぶか、jianmu gemini default を実行します。jianmu が書いたものが取り除かれ、自分のキー、サインイン方法、モデルが戻ります。

Claude Code や Codex も使っていますか？ Claude Code で他のモデルと Codex で他のモデルを参照してください。困ったときは Discord で質問してください。
